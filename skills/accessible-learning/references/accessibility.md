# Accessibility Checks by Artifact Type

## Documents and PDFs

- Check headings, lists, tables, links, reading order, descriptive alternative text, contrast, type size, and plain-language structure.
- Verify in the source file when possible. A visual PDF inspection cannot confirm tagging, reading order, document language, field labels, or assistive-technology behavior.

## Slide decks

- Check for a clear purpose and one main idea per slide or intentional visual grouping.
- Check font legibility, size relative to intended screen size and viewing distance, contrast, uncluttered layouts, non-color cues, meaningful link text, and accessible charts or diagrams. Ask whether the deck is projected, viewed individually, delivered virtually, or printed before judging size.
- Ensure important visual information is conveyed in speech, notes, or supporting text. Provide participation alternatives for polls, small-group tasks, live demonstrations, and timed work.
- Flag source-file checks: slide titles, reading order, alternative text, built-in layouts, hyperlink targets, and exported-PDF tags.

## E-learning modules and web content

- Check clear navigation, visible focus, keyboard access, captions and transcripts, alternatives to drag-and-drop or timed interactions, meaningful headings, labels, and error feedback.
- Inspect actual behavior before claiming keyboard or screen-reader usability. Content review alone cannot verify it.

## Facilitated learning

- Check agenda clarity, accessible materials in advance, verbal description of meaningful visuals, flexible ways to participate, predictable transitions, adequate processing time, and transparent assessment criteria.

## Practical baseline

Use WCAG 2.2 principles—perceivable, operable, understandable, and robust—as a practical baseline. Use them to identify likely barriers, not to issue a formal conformance result without appropriate technical testing.
